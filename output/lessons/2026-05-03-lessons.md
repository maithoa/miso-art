# What I Learned — 2026-05-03

## Lessons

- **Supabase project setup**
  _I didn't know:_ How to create a Supabase project and get the credentials needed to connect it to the app.
  _Now I know:_ Go to supabase.com → New project → copy the Project URL and `anon` public key from Settings → API. Paste them into `.env` as `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. Run SQL migrations from the dashboard SQL editor to create the schema.

- **Stripe API keys and test mode**
  _I didn't know:_ Where to find Stripe keys and which ones to use during development.
  _Now I know:_ In the Stripe dashboard, Developers → API keys. There are two: a Publishable key (goes in the frontend `.env` as `VITE_STRIPE_PUBLISHABLE_KEY`) and a Secret key (goes in the Supabase Edge Function secrets, never in `.env`). Use the `sk_test_` / `pk_test_` keys during development — they work with the test card `4242 4242 4242 4242`.

- **Stripe → Supabase webhook: which endpoint and which event**
  _I didn't know:_ How to wire Stripe back to Supabase so a payment triggers an order update, and which Stripe event to listen for.
  _Now I know:_ First deploy the `fulfill-order` Edge Function to Supabase (it needs to exist before you can get its URL). Then in Stripe → Developers → Webhooks → Add endpoint, paste the Edge Function URL (`https://<project-ref>.supabase.co/functions/v1/fulfill-order`) and select the event `payment_intent.succeeded` — that's the event that fires after a payment is actually confirmed, not just created. Stripe gives you a Webhook Signing Secret; add that to Supabase Edge Function secrets as `STRIPE_WEBHOOK_SECRET`.

- **Why sub-agent terminals (Dev 1, Dev 2) aren't visible**
  _I didn't know:_ Why I couldn't see separate terminals for each agent while the orchestrator was running.
  _Now I know:_ The sub-agents (Dev 1, Dev 2) run as Anthropic API calls inside `agents/orchestrator.js` — they are not separate processes or terminal sessions. All their output is captured by the orchestrator and written to files in `.scratch/`. There is no separate terminal to watch; the agents work silently in the background and the results appear in the output files when they finish.

- **Deno TypeScript errors in Edge Functions**
  _I didn't know:_ Why VS Code showed "Deno is not defined" and missing property errors inside `supabase/functions/`, even though the code was correct.
  _Now I know:_ VS Code uses the Node.js TypeScript server by default, which doesn't know about Deno globals. Two fixes needed: (1) add `"deno.enablePaths": ["supabase/functions"]` to `.vscode/settings.json` so the Deno extension takes over for that folder (requires the Deno VS Code extension to be installed); (2) add `supabase/functions/deno.json` with `"compilerOptions": { "lib": ["deno.window"] }` so TypeScript resolves Deno's type definitions. Additionally, when using `Map.get()`, TypeScript can't infer the value type — you need to write `new Map<string, ProductRow>(...)` explicitly so `.get()` returns the right type.
